# 007 — r01-r05-scan

## Goal
Implement the FastAPI server, the `/scan` background processing endpoint, the `reader.py` core parsing logic, and detection rules R01-R05.

## Spec sections
> §6b. Endpoint contract
> | `POST` | `/scan` | `_scanning.html` | accepts multipart, creates a `job_id`, runs scan |
> | `GET`  | `/scan/{job}` | `_scanning.html` or `_report.html` | polled by client |

> §4. Audit rules
> Every rule is a class extending `Rule`.
> R01: Formula contains `#REF!`
> R02: Cell currently evaluates to an error
> R03: Error code pasted in as literal text
> R04: Arithmetic directly on a cell that returns `""`
> R05: Reference to a sheet that doesn't exist

## In scope / out of scope
- **In scope**: FastAPI app skeleton, job storage for background scans, parsing `<f>` and `<v>` from worksheets, detecting R01-R05.
- **Out of scope**: Implementing the fix logic (`<CellEdit>`) for R01-R05 (Milestone 5), frontend UI for checking/unchecking issues, applying patches.

## Ponytail ladder
- Does this need to exist? Yes, it's the core engine of the app.
- Is it already in the codebase? No, only the `inventory.py` and `formula.py` stubs exist.
- Does the stdlib handle it? `zipfile` handles unzipping. FastAPI handles the web requests.
- Can it be one line? No, multiple files and components are interacting.

## Plan
1. Scaffold FastAPI in `backend/app.py` with dummy templates.
2. Extend `reader.py` to parse sheets and extract formulas/values.
3. Build `Rule` base class and finding registry in `backend/audit/base.py`.
4. Build `rules_formula.py` containing R01-R05 logic.
5. Create `sokho_google.xlsx` mock to drive TDD.

- Mock `sokho_google.xlsx` is scanned.
- Detected errors exactly match expected numbers and locations.

## Rollback
